# Atte Kit (`@atte/kit`)

`@atte/kit` is the transport-independent authority for Atte's editor tools, MCP catalog, skills, prompts and policies. It imports schema packages only; the API and stdio bridge consume it.

## Catalog authority

`src/mcp-tool-catalog.ts` defines every HTTP MCP tool once with `audience`, `category`, `scope`, `spends` and `profiles`. `MCP_TOOLS` contains 147 tools (82 internal and 65 public); `ATTE_PUBLIC_TOOLS` is the exact public subset derived from that same list. MCP declarations derive from the public subset through `src/tool-adapters.ts`.

The external boundary uses camelCase and seconds. `compile_edit.calls[].arguments` is validated and translated through the single mapping table in `src/compile-edit-boundary.ts` before the existing internal snake_case compiler produces tick-based project operations. In particular, public `ripple_trim_clip.offsetSeconds` maps to internal `offset_seconds`, which is rounded onto the active sequence frame grid before the editor receives its frame offset; `offsetFrames` is not a public key. Persisted `shots` analysis feeds that compiler: `apply_transition`, `punch_in`, and `add_graphic` accept `snap: "shot"`, while `add_air { atCutSeconds, seconds, mode? }` authors measured breathing room at a cut. Unknown keys return a structured error with public valid keys and an example.

Preparation is separate from mutation: `prepare_project` batches local import, optional placement and brief storage with requested analyses behind one `get_job { kind: "prepare" }` handle. `compile_edit` is read-only and already simulates; it returns both the complete transaction and a server-side `transactionRef` valid for ten minutes. `commit_transaction` accepts exactly one of those forms and remains the commit point. Raw transactions still use `simulate_transaction` before commit. `checkpoint_project` writes only for create/restore actions. `prepare_project` spends only when its analyses explicitly include `description`; `analyze_asset` spends for description or non-technical postproduction; status/cancel and evidence reads do not dispatch providers. `review_project` spends for frames or delivery; `start_job` is the generic job spend point.

## Whole-video inference

Use `list_models` then `get_model` before selecting a Vidaio operation. The API lists `vidaio/upscale/standard|premium` only when available; it takes `videoUploadUrl: "/v1/uploads/<id>/content"`, composed from the `{id,mimeType,bytes,sha256}` receipt returned by `upload_inference`, plus `upscaleFactor: 2|4`. `vidaio/compress/standard|premium` takes the same internal upload path and `compressionLevel: "Low"|"Medium"|"High"` (Low favors smaller files, Medium balances size and quality, High preserves more quality). Keep the original unchanged; save a project version when working in a project. Quote without spending, start once with an idempotency key, poll/download the output, and import it as a separate Library asset. A Library asset URL belongs to a different store: prefer a discovered `video_upscale` or `video_compress` capability with its `source.url`, descriptor `providerId`, and `routingTier: "manual"`; otherwise download it locally and use `upload_inference`. Server-side model availability, actual source dimensions/duration and prices are authoritative. Vidaio has no standalone restoration/denoise operation or documented cancellation endpoint.

## Video diagnosis

For a 15–180 second source video, `analyze_asset { analysis: "postproduction" }` returns a persistent analysis job immediately. Read it through `get_job { kind: "analysis" }` or `get_asset_evidence`; use `action: "cancel"` to stop and `force: true` only for an explicit retry. `maxCostUsd` bounds the analysis separately from conversation, project, account and connection limits. Source shots, frame coverage, segmented listening, scenes and contextual priorities retain evidence references. A brief change reuses valid source evidence. A diagnosis never prepares or applies edits automatically. Legacy/technical-only reads do not silently upgrade to paid analysis. See [source video diagnosis](https://github.com/attelierai/attelier_app/blob/main/docs/VIDEO_DIAGNOSIS.md) for lifecycle and evidence limits.

## MCP-native media

Tool results keep their JSON text block first for compatibility. `render_frame` then embeds an `image/png` block at the requested width (default 960, hard maximum 1920). Range previews, frame-review evidence, Library proxies/posters and completed render outputs are emitted as `resource_link` blocks with absolute authenticated API URLs; large video bytes are not duplicated into JSON/base64.

## Skills

Agent discovery exposes 35 operational skills. Every fenced JSON call in a registered skill is CI-validated against the generated public schemas, including the nested `compile_edit` boundary. Design-only proposals stay outside the runtime registry until they have an executable implementation.

## Internal compatibility

Studio and the in-process Atte harness select only `documentary + shared`, `ad + shared`, or `shared` tools from the persisted project quality profile. Project-scoped internal MCP discovery applies the same filter; unscoped administrative discovery retains the full compatibility catalog. External agents always see the invariant 65-tool subset through `attelier-mcp`. Add or change a definition in the catalog authority, then run the generator and the catalog drift tests.
